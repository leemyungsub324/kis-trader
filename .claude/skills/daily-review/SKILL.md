# kis-trader 일일 점검

장 마감 뒤(15:55 장후 스캔 이후 권장) 하루 매매를 점검한다. 목표는 두 가지다.
1. **성과**: 오늘 무엇을 사고팔았고, 손익이 어떤가.
2. **대응**: 알고리즘(전략 규칙·엔진 동작)이 오늘 시장에 맞게 움직였는가. 문제가 있으면 개선 후보를 남긴다.

**코드나 config 를 고치지 않는다.** 개선은 후보로만 적고, 고칠지는 사용자에게 묻는다.
주문·청산 등 계좌에 영향을 주는 동작도 하지 않는다.

## 1. 자료 모으기

```bash
python3 scripts/daily_report.py            # 로그의 마지막 거래일
python3 scripts/daily_report.py 2026-11-19 # 인자로 날짜 지정(사용자가 날짜를 말했으면 그 날짜)
```

표준 라이브러리만 쓰므로 호스트에서 바로 돈다(sudo·Docker 불필요, API 호출 없음).
출력 섹션: 1 운영 상태 / 2 주문과 체결 / 3 손익 / 4 시장 상황 / 5 보유·후보 신호 점검 / 6 누적 거래.

필요할 때만 더 본다.
- 원 로그: `grep '"ts": "<날짜>' logs/kis-trader.log` (JSON 줄. 일봉 갱신 줄은 무시)
- 전략 규칙: `config.yaml`(민감정보 포함 — **키·시크릿·계좌·토큰 값은 절대 출력하지 말 것**, `strategies:` 블록만 본다), `kis_trader/strategies/*.py`
- 엔진 동작: `kis_trader/engine.py` (phase 시간표, closing, _enter_plans, brief)
- 과거 리포트: `reports/` (어제와 비교, 같은 문제가 반복되는지)
- 백테스트 기준치: `data/backtest_reversal_*.txt` (투매 반등 20일 보유: 승률 약 67%, 평균수익 약 +2.9%, 평균보유 8.5일)

## 2. 점검 항목

### A. 운영 (엔진이 정상적으로 돌았나)
- 재시작 횟수와 이유. 장중 재시작이면 사용자에게 확인할 일로 남긴다.
- WARNING/ERROR: 통신 오류 몇 건은 정상(재시도). 같은 오류 반복, "연속 오류", "루프 오류"는 문제.
- 휴장 판정: "휴장으로 판단, 오늘은 쉼"이 찍혔는데 지수 일봉(섹션 4)에 그날 거래가 있으면 **오판**(지연 개장일 등).
- 시황 브리핑: 09~15시 7회가 기준. 빠진 시각과 이유.
- 장후 스캔 완료 여부, 국면, 후보 수.
- 시간표: 마감 단계는 14:58~15:20, 장후 스캔은 15:40 이후여야 한다. 벗어난 시각의 주문·청산이 있으면 문제.

### B. 주문·체결 (규칙대로 실행됐나)
- 사다리 매수가가 전일 종가 −3/−6/−10틱인지, 갭 조건으로 건너뛴 종목이 있는지.
- 체결률. "⚠ 가격이 뚫렸는데 미체결"은 체결 동기화나 주문 상태 문제일 수 있으니 반드시 짚는다.
- 익절 주문이 체결 수량에 맞춰 다시 걸렸는지, 익절가와 당일 고가 차이(아깝게 놓친 익절).
- 손절·기간만료·시가청산 매도가 있었다면 사유와 시각이 규칙과 맞는지.

### C. 성과
- 실현 손익(매도 체결분), 보유 평가손익, 오늘 하루 변동. 계좌(equity0) 대비 비중.
- 종목별로 지수 대비 성과(섹션 5의 "지수대비").
- 누적: 지금까지의 매수·매도 건수, 청산 사유 분포. 표본이 10건 미만이면 **결론 내리지 말고** 관찰로만 적는다.

### D. 시장 대응 (알고리즘 판단이 시장과 맞았나)
- 국면(BULL/NEUTRAL/BEAR)과 오늘 지수 움직임. 급등주 종가베팅은 BEAR 에서 꺼져 있다.
- 투매 반등의 전제는 "시장 전체 급락에 같이 빠진 종목"이다. 섹션 5에서
  - **최근5일 악재성폭락**: 개별 악재 종목일 가능성(전략 문서상 이후 성과가 나쁨)
  - **지수는 5일 반등 중**: 낡은 급락 신호일 가능성
  가 붙은 종목은 신호의 질이 낮은 것으로 본다. (crash_days·mkt_ret5_max 필터는 2026-11-16 백테스트에서 수익을 줄여 꺼 둔 상태 — 실거래 사례가 쌓이면 재검토 근거로 기록)
- 보유 종목이 "종가>5일선(반등 진행)"인데 익절 전이면 반등을 잘 잡고 있는 것. 지수와 반대로 계속 빠지면 주의.
- 같은 종목이 이미 보유 중인데 다시 후보로 뜨는 것은 정상(엔진이 건너뜀).

## 3. 리포트 쓰기

`reports/<날짜>.md` 로 저장하고(폴더 없으면 생성, git 에는 안 올라감), 채팅에는 요약만 보여준다.
수치는 스크립트 출력에서 가져오고 지어내지 않는다. 출력에 없는 것은 "확인 못함"으로 쓴다.

```markdown
# 매매 점검 <날짜>

## 한 줄 요약
<성과 한 문장 + 대응 평가 한 문장>

## 성과
| 구분 | 금액 | 비고 |
|---|---|---|
| 실현 손익 | | |
| 보유 평가손익 | | 매입 → 평가 |
| 오늘 하루 변동 | | 계좌 대비 % |

보유: 종목 · 수량 · 평단 → 종가 · 평가% · 보유일 · 지수대비

## 시장
지수 등락·장중폭·5일·20일고점대비·국면, 오늘 장의 성격 한두 문장

## 알고리즘 대응 평가
- 잘한 점:
- 문제/의심:   (근거 수치와 함께. 운영 문제와 전략 문제를 구분)
- 판정: 양호 / 주의 / 문제

## 내일 볼 것
- 후보 종목과 신호 질 평가, 걸려 있는 익절·손절 가격, 기간만료 임박 종목

## 개선 후보 (사용자 결정 필요)
- 무엇을 · 왜(오늘의 근거) · 검증 방법(백테스트/며칠 더 관찰)
```

## 4. 마무리

- 채팅 답변: 한 줄 요약, 성과 표, 판정과 핵심 문제 2~3개, 리포트 파일 경로.
- 개선 후보가 있으면 "고칠지" 하나만 묻는다. 사용자가 원하면 그때 코드 수정 → 테스트(Docker test 단계) → 재시작 순서로 진행한다.
- 같은 문제가 이전 리포트에도 있었다면 "반복"이라고 명시한다.
